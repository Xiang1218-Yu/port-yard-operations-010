# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- **作业事件指挥台**：跨箱、跨任务的统一事件空间
  - 创建事件（设备故障/海关管制/闸口拥堵等）、严重度、影响范围（航次/区块/设备/箱号/闸口车道）与现场指挥人
  - 处置阶段流转（发现接报 → 先期封控 → 联动处置 → 恢复评估 → 关闭）与指挥权交接
  - 发布临时操作规则：受影响任务**暂停**或**改派**至接替设备，规则随范围动态 reconcile（新建/改位/删除任务自动纳管或退出）
  - 解除规则必须**逐条人工复核**：通过才恢复事件前基线（状态/设备/原有阻塞原因），可驳回让规则继续生效
  - 恢复失败（如基线设备仍在维护）挂账并可在条件具备后重试；同一任务可被多个事件叠加覆盖，全部覆盖解除后才恢复
  - 关闭顺序校验：有未解除规则/未恢复工作时拦截，支持带尾欠强制关闭并转入全局恢复台账；事件关闭后仍可补录证据
  - 去重通知（同一规则事件不重复推送）、完整处置时间线/交接/证据/通知审计
  - 控制台展示实际受影响对象（任务、箱、设备、预约、多事件覆盖标记）与尚未恢复的工作，而非描述文本
- React 控制台支持船期驾驶舱、事件指挥台、闸口操作、堆场热区与设备任务操作

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额和优化求解器。
